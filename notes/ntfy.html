freeknet ntfy guide

how the join-notification system works, and how to control it.

tl;dr

When someone joins freeknet, server.js POSTs a tiny HTTP message to https://ntfy.sh/{your-topic}. Anyone subscribed to that topic — your phone, a browser tab, a terminal — receives the push within ~1 second. ntfy.sh is a free public pub/sub relay; no accounts, no infrastructure.

your topic

This is the secret-ish identifier for your notification stream. Anyone who knows it can read your pushes and send fake ones. Don't share publicly; don't commit to a public repo.

how the flow works

1
player joins
WebSocket sends {t:'join'} to server.js
→
2
batched
joins within 5s collapse into one push
→
3
POST ntfy.sh
tiny HTTP with the topic in the URL path
→
4
fan-out
ntfy pushes to every subscriber instantly

ntfy.sh is the message broker. It doesn't know or care what freeknet is — just that your server is a publisher and your phone is a subscriber on the same topic string. Same idea as Redis pub/sub or MQTT, but with no setup and a free public broker.

subscribing

phone (recommended)

  • Install the ntfy app — iOS, Android Play Store, F-Droid
  • Tap +, paste your topic name (above), save
  • Per-topic settings: mute, set DND schedule, change sound, custom icon

browser (no install)

Open ntfy.sh/{your-topic} in any tab. Notifications stream into the page. You can grant browser-push permission and get desktop notifications without keeping the tab in focus.

terminal

curl -s ntfy.sh/freeknet-stew-65fd0ae97959/json | jq

Long-polling stream of new messages as JSON-lines. Hit ctrl-C to stop.

the server code

This is the relevant block in server.js:

const NTFY_TOPIC = process.env.NTFY_TOPIC || '';
const NTFY_URL = NTFY_TOPIC ? `https://ntfy.sh/${NTFY_TOPIC}` : '';

// debounce: bursts collapse into one push (avoids spam from bots / refresh loops)
let pendingJoins = 0, notifyTimer = null;
const NOTIFY_BATCH_MS = 5000;

function notifyJoin() {
  if (!NTFY_URL) return;                 // no-op if env unset
  pendingJoins++;
  if (notifyTimer) return;
  notifyTimer = setTimeout(() => {
    const count = pendingJoins;
    const total = players.size;
    pendingJoins = 0; notifyTimer = null;
    const msg = count === 1
      ? `someone joined freeknet (${total} online)`
      : `${count} joined freeknet (${total} online)`;
    fetch(NTFY_URL, {
      method: 'POST',
      body: msg,
      headers: { Title: 'freeknet', Tags: 'wave' },
    }).catch(err => console.error('[ntfy] push failed:', err.message));
  }, NOTIFY_BATCH_MS);
}

Called from the t: 'join' WS handler. If NTFY_TOPIC is empty (e.g., in local dev), all notifications silently no-op.

changing the topic

ssh root@freeknet.duckdns.org

# edit /etc/freeknet.env — single line:
#   NTFY_TOPIC=your-new-name-here
nano /etc/freeknet.env

systemctl restart freeknet

# verify env loaded
systemctl show freeknet -p Environment

The systemd unit auto-loads /etc/freeknet.env at start (because of EnvironmentFile=-/etc/freeknet.env in deploy/freeknet.service). Restart picks up changes.

troubleshooting

I don't get notifications

  • Hit the send test push button above. If your phone gets that, the server is the broken piece. If it doesn't, your subscription is broken.
  • Confirm env loaded: ssh root@freeknet.duckdns.org 'systemctl show freeknet -p Environment' — should include NTFY_TOPIC=...
  • Tail for push errors: ssh root@freeknet.duckdns.org 'journalctl -u freeknet -f | grep ntfy'
  • Tail for joins (to confirm they're happening at all): journalctl -u freeknet -f | grep join

too many notifications

Bots from freeknet-bot will each trigger a notification on join. Options, in order of least → most invasive:

  • Mute in the ntfy app (per-topic DND schedule)
  • Tighten the batch window — set NOTIFY_BATCH_MS = 60000 in server.js (collapse a full minute of joins into one ping)
  • Skip pushes when room is already populated — wrap with if (players.size < 3)
  • Filter known-bot IDs — bots don't self-identify today, but you could give the bot a join handshake field and filter on it

stop notifications entirely

ssh root@freeknet.duckdns.org
rm /etc/freeknet.env
systemctl restart freeknet

With NTFY_TOPIC unset, notifyJoin() no-ops. The game keeps working normally; logs still record joins.

I changed the topic — old one still works?

ntfy topics are anonymous and stateless. The old one is "orphaned" — no one is pushing to it. If you're still subscribed in the app, you just won't see anything. Safe to remove from the app or ignore.

can someone spam my topic?

Yes — anyone who knows the topic string can POST to it. The topic is treated like a shared secret. If it leaks, generate a new one (see changing the topic above) and update the app subscription. ntfy.sh also supports reserved topics + auth for ~$5/mo if you ever want hard guarantees.
